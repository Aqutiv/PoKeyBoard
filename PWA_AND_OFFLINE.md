# PWA and offline

## Manifest

Generated by vite-plugin-pwa from `vite.config.ts`: name/short_name **PoKeyBoard**, `display: standalone`, stable `id`, theme `#1d1a17` on background `#171412`, standard + maskable icons (from `assets/branding/pokeyboard-icon-master.png` via `scripts/build-icons.mjs`) and an Apple touch icon linked in `index.html`. `start_url`, `scope`, and `id` all derive from the single configurable base path (`POKEYBOARD_BASE`).

## Service worker (src/pwa/service-worker.ts, Workbox injectManifest)

- **Precache:** the app shell only — JS/CSS/HTML/icons/fonts, ~2.0 MB. Piano samples are explicitly excluded from precache. `npm run build` prints the live number (`precache N entries (… KiB)`); trust that over this line, which has drifted before.
- **Navigation fallback:** every navigation serves the precached shell, so the app starts offline. Hash routing keeps this to a single URL.
- **Runtime caching:** `**/piano/**` → Cache First into `pokeyboard-piano-samples-v3` (immutable versioned filenames; superseded generations listed in `STALE_PIANO_SAMPLE_CACHES` are deleted on service worker activation). **All** pianos share that one cache — 91 entries each, against an `ExpirationPlugin` cap of 512, which is deliberate headroom because LRU eviction is silent and would quietly falsify "available offline". The same named cache backs Settings → **Download piano for offline use** (progress by manifest bytes) and **Delete downloaded samples**, both scoped to one piano: delete enumerates `cache.keys()` by pack path rather than dropping the whole cache, so the other piano stays offline-ready and the reported state cannot disagree with what is stored. Deleting samples never touches takes, and the cache purges itself first under quota pressure so IndexedDB takes survive.
- **Not cached:** import from a pasted link matches no runtime route, so it passes straight through to the network and needs a live connection. Adding a catch-all route would start intercepting those downloads — don't, without revisiting `previewImportUrl`.

## Updates

A new deploy makes the browser install a **waiting** worker; `updateManager` (workbox-window) surfaces "update available", and activation happens only when the user applies it in Settings — the button is disabled while recording/playing/exporting, and nothing ever auto-reloads mid-session. Applying sends `SKIP_WAITING` and reloads on `controlling`.

## Installation

`beforeinstallprompt` is captured where browsers fire it (Settings shows an Install button; a dismissal starts a 14-day quiet period). iOS has no programmatic prompt: Settings shows Share → **Add to Home Screen** instructions and warns that the installed app may use a **separate storage context** — export a JSON backup before switching, and prefer the installed icon for important takes.

## Offline matrix

Per selected piano — each one downloads and is deleted on its own.

| Asset                 | First visit | After visit            | After "Download piano" |
| --------------------- | ----------- | ---------------------- | ---------------------- |
| App shell             | network     | ✓ offline              | ✓ offline              |
| Core piano (~12MB)    | on demand   | keys played are cached | ✓ offline              |
| Full piano (~24-28MB) | on demand   | partial                | ✓ offline              |
| Takes (IndexedDB)     | local       | local                  | local                  |

## Caching headers (host configuration)

| Path                        | Header                                               |
| --------------------------- | ---------------------------------------------------- |
| `/index.html`               | `Cache-Control: no-cache`                            |
| `/service-worker.js`        | `Cache-Control: no-cache`                            |
| `/manifest.webmanifest`     | `Cache-Control: no-cache` (or short max-age)         |
| `/assets/*` (hashed js/css) | `Cache-Control: public, max-age=31536000, immutable` |
| `/piano/*` (versioned pack) | `Cache-Control: public, max-age=31536000, immutable` |
| `/icons/*`                  | `public, max-age=86400`                              |
