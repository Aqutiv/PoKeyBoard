# PWA and offline

## Manifest

Generated by vite-plugin-pwa from `vite.config.ts`: name/short_name **PoKeyBoard**, `display: standalone`, stable `id`, theme `#1d1a17` on background `#171412`, transparent standard icons (from `assets/branding/pokeyboard-emblem-transparent.png`), backed maskable and Apple touch icons (from `assets/branding/pokeyboard-icon-master.png`), all generated via `scripts/build-icons.mjs`. `start_url`, `scope`, and `id` all derive from the single configurable base path (`POKEYBOARD_BASE`).

## Service worker (src/pwa/service-worker.ts, Workbox injectManifest)

- **Precache:** the app shell only — JS/CSS/HTML/icons/fonts, ~2.0 MB. Piano samples are explicitly excluded from precache. `npm run build` prints the live number (`precache N entries (… KiB)`); trust that over this line, which has drifted before.
- **Navigation fallback:** every navigation serves the precached shell, so the app starts offline. Hash routing keeps this to a single URL.
- **Runtime caching:** `**/piano/**` → Cache First into `pokeyboard-piano-samples-v3` (immutable versioned filenames; superseded generations listed in `STALE_PIANO_SAMPLE_CACHES` are deleted on service worker activation). **All** pianos share that one cache — 121 entries each for Salamander and the Steinway, 91 for Headroom, 376 with all four pianos downloaded, against an `ExpirationPlugin` cap of 512, which is deliberate headroom because LRU eviction is silent and would quietly falsify "available offline". The same named cache backs the **Download** and **Delete** buttons on each piano card in Settings → **Sound** (progress by manifest bytes), both scoped to that one piano: delete enumerates `cache.keys()` by pack path rather than dropping the whole cache, so the other piano stays offline-ready and the reported state cannot disagree with what is stored. Deleting samples never touches takes, and the cache purges itself first under quota pressure so IndexedDB takes survive.
- **Files shared between generations:** Salamander's v4 and the Steinway's v2 add a pianissimo layer to v3's and v1's three, and list those by relative path (`../salamander-grand-v3/C4v5.sample`). The URL resolves to the one its own pack published, so the cache holds each file once, and a player who had a piano cached already fetches only the new layer. A piano saved for offline use before its pianissimo layer existed shows its **Download** button again. Downloading adds only that layer, and until then its soft notes play the soft recording, as they did before. A piano's pianissimo recordings load behind it once it plays, so they never delay its first notes (see ARCHITECTURE.md).
- **Not cached:** import from a pasted link matches no runtime route, so it passes straight through to the network and needs a live connection. Adding a catch-all route would start intercepting those downloads — don't, without revisiting `previewImportUrl`.

## Share links

A take's share link carries the whole take after `#` (see TAKE_FORMAT.md, Share links), and a Library link names a track.

- **Offline:** a take link needs nothing but the app shell — it decodes and imports with no connection. A Library link to an authored track opens offline too, since those are built into the app. A Classics score is fetched the first time it is opened, and runtime-cached from then on; a link to one never opened, followed offline, says the piece could not be downloaded and leaves the Library showing it.
- **iOS:** a link tapped in Messages or Mail opens in Safari, with Safari's storage — not the installed Home Screen app's, which keeps its own. The take is imported where the link was opened. To have it in the installed app, paste the link into Takes → Import → From a link (URL) there, or send the take as a file.
- **Nothing is fetched to open one,** and nothing is uploaded to make one: the fragment never reaches a server, this app's host included. It is not secret, though. The link stays in the browser's history, and in whatever app it was pasted into — a chat, a mail, a note — and anyone who has it can open the take.

## Updates

A new deploy makes the browser install a **waiting** worker; `updateManager` (workbox-window) surfaces "update available", and activation happens only when the user applies it in Settings, which offers it above its sections — the button is disabled while recording/playing/exporting, and nothing ever auto-reloads mid-session. Applying sends `SKIP_WAITING` and reloads on `controlling`.

## Installation

`beforeinstallprompt` is captured where browsers fire it (Settings → App shows an Install button; a dismissal starts a 14-day quiet period). iOS has no programmatic prompt: Settings → App shows Share → **Add to Home Screen** instructions and warns that the installed app may use a **separate storage context** — export a JSON backup before switching, and prefer the installed icon for important takes. A backup carries the takes and settings only: Learn progress and the Library's best practice results stay behind in Safari, and the installed app starts them afresh.

Desktop Chromium treats installed-app icon changes as identity updates. The
transparent icon uses a new manifest URL so current Chromium releases can offer
**Review app update**; on browsers that do not update installed icons, uninstall
and reinstall the PWA. Fresh installs use the transparent icon immediately.

## Offline matrix

Per selected piano — each one downloads and is deleted on its own.

| Asset                 | First visit | After visit            | After "Download piano" |
| --------------------- | ----------- | ---------------------- | ---------------------- |
| App shell             | network     | ✓ offline              | ✓ offline              |
| Core piano (~11-18MB) | on demand   | keys played are cached | ✓ offline              |
| Full piano (~24-39MB) | on demand   | partial                | ✓ offline              |
| Takes (IndexedDB)     | local       | local                  | local                  |

## Caching headers (host configuration)

| Path                        | Header                                               |
| --------------------------- | ---------------------------------------------------- |
| `/index.html`               | `Cache-Control: no-cache`                            |
| `/service-worker.js`        | `Cache-Control: no-cache`                            |
| `/manifest.webmanifest`     | `Cache-Control: no-cache` (or short max-age)         |
| `/assets/*` (hashed js/css) | `Cache-Control: public, max-age=31536000, immutable` |
| `/piano/*` (versioned pack) | `Cache-Control: public, max-age=31536000, immutable` |
| `/icons/*`                  | `public, max-age=86400`                              |
